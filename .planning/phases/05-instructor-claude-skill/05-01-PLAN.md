**YAML frontmatter** — name, description with multi-line trigger phrases (invoked via /facilitate, "start the lab", "next section", "continue", any facilitation question during a live session).

**Objective section** — one paragraph: what the skill is, who it is for, how it works (sequential guide through INSTRUCTOR_GUIDE.md sections, full coaching script per section, instructor controls the pace).

**On Invocation section** — explicit read instructions for three files before any response:
1. `INSTRUCTOR_GUIDE.md` — primary coaching script
2. `AGENTS.md` — Snowflake schema, business rules, key paths
3. `LAB_INSTRUCTIONS.md` — participant-facing guide

After reading all three files, open with a brief orientation (2-3 sentences: what the skill does, how to advance, ~90 min total) then immediately present Section 1 content. Do not add lengthy usage instructions — the instructor may be about to go live.

**Session Flow section** — state machine rules:
- Present one section at a time; after presenting, wait for instructor input
- Advance when instructor says: "next" / "continue" / "move on" / "ready" / a section name or number / "let's go" / any natural language indicating readiness
- Do NOT advance automatically — instructor controls timing
- Jump navigation: if instructor says "go to Section 6" or "skip to Task 2", jump directly without reciting intermediate sections
- If instructor asks a mid-section question, answer immediately from loaded context, then note current position ("You're on Step X.X — ready to continue?")

**Section Delivery section** — per-section format rules:
- Always include: section header with timing cue, ALL steps in order with step labels matching INSTRUCTOR_GUIDE.md, participant prompts in code blocks (verbatim), expected outputs for verification steps, watch-for callouts, group callout cues, fallback/conditional prompts in brackets
- Verification hints phrased as instructor relay prompts: "Ask participants to..." or "Tell participants to confirm..." — NOT raw SQL
- Do not summarize or abbreviate any step; present the full coaching script
- Close each section with: "Ready for the next section?" (or equivalent readiness prompt)

**Ad Hoc Questions section** — question routing rules:
- Data/schema questions → reason from AGENTS.md
- Participant-step questions → reason from LAB_INSTRUCTIONS.md
- Troubleshooting questions → check INSTRUCTOR_GUIDE.md troubleshooting table first
- Never say "I don't know" when the answer can be derived from loaded files

**Constraints section** — hard rules:
- Do not execute any SQL or Snowflake commands. All verification is done by participants in their own environments. Present verification steps as relay prompts only.
- Do not maintain per-participant state. Track the instructor's section position only.
- Do not auto-advance through sections. Always wait for instructor input.
- Section 7 is discussion-only and not tracked — if the instructor reaches end of Section 6, offer a brief wrap-up note and confirm session complete.

Skill file should be ~80-100 lines. If it exceeds ~100 lines, content has likely been inlined from INSTRUCTOR_GUIDE.md — that is wrong. Content stays in INSTRUCTOR_GUIDE.md; the skill only instructs Claude how to deliver it.
