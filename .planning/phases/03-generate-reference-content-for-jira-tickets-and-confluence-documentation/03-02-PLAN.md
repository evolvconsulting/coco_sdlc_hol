  <action>
Create scripts/ directory and write scripts/create-atlassian-artifacts.sh -- a bash script that creates all Jira and Confluence artifacts via REST API.

The script must:

**1. Configuration and auth setup:**
- Accept API token via environment variable ATLASSIAN_API_TOKEN or prompt for it at runtime
- Use email: trent.foley@evolvconsulting.com
- Base URL: https://evolv-coco-sdlc-hol.atlassian.net
- NEVER store the token in the script file itself
- Construct Basic auth header: `echo -n "email:token" | base64`
- Validate auth by making a simple API call (e.g., GET /rest/api/3/myself) and exit with clear error if auth fails

**2. Pre-flight checks:**
- Verify EPA Jira project exists: GET /rest/api/3/project/EPA
- Verify EPA Confluence space exists: GET /wiki/rest/api/space/EPA
- Discover custom field IDs for Story Points: GET /rest/api/3/field, parse for "Story point" or "Story Points" (case-insensitive), store the field ID
- Discover board ID: GET /rest/agile/1.0/board?projectKeyOrId=EPA
- Discover or create a sprint: GET /rest/agile/1.0/board/{boardId}/sprint, find an active sprint or create one named "Sprint 3" (suggesting project history)
- Create components if they don't exist: "Backend", "Frontend", "Data Platform" via POST /rest/api/3/component
- Print discovered field IDs and sprint info for debugging

**3. Create Jira Epic:**
- POST /rest/api/3/issue with issuetype "Epic"
- Summary from EPA-epic.wiki content
- Description: Convert the wiki markup content from docs/jira/EPA-epic.wiki into ADF JSON
- Build ADF JSON programmatically in the script (construct the JSON structure with headings, paragraphs, ordered lists, panels, etc. matching the wiki content)
- Labels: ["platform", "analytics", "enhancements"]
- Capture returned issue key (e.g., EPA-1) and store in EPIC_KEY variable
- Print: "Created epic: $EPIC_KEY"

**4. Create two main stories (linked to epic):**
- For each of EPA-retry-success-rate.wiki and EPA-kpi-card.wiki:
  - POST /rest/api/3/issue with issuetype "Story"
  - parent: {"key": "$EPIC_KEY"}
  - Convert wiki markup to ADF JSON for description
  - Set priority, labels, story points (via discovered custom field ID), and components
  - EPA-retry-success-rate: Priority High, story points 5, labels [dbt, semantic-view, metric, cortex-agent], component "Data Platform"
  - EPA-kpi-card: Priority Medium, story points 3, labels [frontend, dashboard, kpi], component "Frontend"
  - Assign both to the discovered/created sprint (via sprint custom field ID)
  - Capture returned issue keys, store as TICKET1_KEY and TICKET2_KEY
  - Print: "Created story: $TICKET1_KEY (retry success rate)" and "Created story: $TICKET2_KEY (KPI card)"

**5. Create three backlog stories (linked to epic, no sprint):**
- For each backlog .wiki file:
  - POST /rest/api/3/issue with issuetype "Story"
  - parent: {"key": "$EPIC_KEY"}
  - Convert wiki markup to ADF JSON for description
  - Set labels but NO sprint assignment, NO story points (backlog items are unprioritized per CONTEXT.md)
  - Priority: Low
  - Capture keys and print

**6. Create Confluence data dictionary page:**
- Read docs/confluence/data-dictionary.wiki
- Try the wiki-to-storage conversion endpoint first: POST /wiki/rest/api/contentbody/convert/storage with the wiki content
- If conversion endpoint fails (deprecated), fall back to constructing storage format XHTML directly from the wiki content (the script should have a fallback XHTML version built from the same content)
- POST /wiki/rest/api/content/ with type "page", title "Payment Analytics Data Dictionary", space key "EPA", body in storage format
- Capture the page URL from the response
- Print: "Created Confluence page: $PAGE_URL"

**7. Summary output:**
- Print a summary block with all created artifact keys and URLs:
  ```
  === Atlassian Artifacts Created ===
  Epic:     $EPIC_KEY
  Ticket 1: $TICKET1_KEY (retry success rate metric)
  Ticket 2: $TICKET2_KEY (KPI card)
  Backlog:  $BACKLOG1_KEY, $BACKLOG2_KEY, $BACKLOG3_KEY
  Confluence: $PAGE_URL

  Update HANDS_ON_LAB.md:
    [TICKET-1] -> $TICKET1_KEY
    [TICKET-2] -> $TICKET2_KEY
    [CONFLUENCE-DATA-DICTIONARY-URL] -> $PAGE_URL
  ===
  ```

**ADF JSON construction approach:**
Rather than parsing wiki markup at runtime, build the ADF JSON inline in the script for each ticket. Read the .wiki files for reference content, but construct the ADF structure directly. This avoids needing a wiki-to-ADF parser.

For each wiki section, map to ADF nodes:
- h2. Heading -> {"type": "heading", "attrs": {"level": 2}, "content": [{"type": "text", "text": "..."}]}
- Paragraph text -> {"type": "paragraph", "content": [{"type": "text", "text": "..."}]}
- *bold* -> {"type": "text", "text": "...", "marks": [{"type": "strong"}]}
- # Ordered list item -> {"type": "orderedList", "content": [{"type": "listItem", ...}]}
- {panel:title=X} -> {"type": "panel", "attrs": {"panelType": "info"}, "content": [...]}

The script should use bash heredocs or printf to construct the JSON payloads. Use `jq` if available for JSON validation, but don't require it as a dependency -- fall back to raw JSON strings.

Make the script executable (chmod +x). Include error handling: check HTTP response codes for every API call, print the response body on failure, and exit on critical failures (auth, project not found). Non-critical failures (e.g., component already exists) should warn and continue.
